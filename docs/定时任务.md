# 定时任务（2026-10-30）

到点自动往群里发消息：**每天播天气 / 按时提醒打卡签到 / 自己写的任意提醒**。

> ⚠️ **改面板界面后必须重跑打包**：DSH 里真正渲染的是打包产物 `lib/client.js`，不是 `panel/index.html`。
> 改完 `panel/index.html` 一定要跑 `node build-client.mjs`，否则「插件代码是新的、界面还是旧的」。
> （2026-10-30 实测事故：op 白名单自检显示 61/61 全放行，日志也确认新代码在跑，但页面上根本没有新标签页——差的就是这一步打包。）

## 在哪儿配

面板 → **⏰ 定时任务**（`/wechat-bot`）：

- 顶部：总开关 `schedulerEnabled`、服务器当前时间
- 中间：任务列表（名称 / 时间 / 动作 / 目标群 / 下次运行 / 上次结果 / 操作）
- 下面：新增-编辑表单（保存、预览下次时间、取消编辑）
- 最下面：运行日志（最近 50 条，可清空）

也可以在对话里用工具 `wechat_bot_schedule`（list / add / remove / toggle / run）。

## 时间怎么填

| 类型 | 字段 | 例子 |
|---|---|---|
| 每天 | `time` | `09:30` |
| 每周 | `time` + `weekdays`（1=周一 … 7=周日） | 每周一三五 09:00 |
| 每隔 | `everyMinutes` | 每 60 分钟 |
| 只跑一次 | `at` | `2026-11-01T09:00` |
| cron | `cron`（五段：分 时 日 月 周） | `0 9 * * 1-5` = 工作日 9 点 |

cron 支持 `*`、`*/10`、`1-5`、`1,3,5`；周日可以写 0 或 7。

## 动作怎么填

| 类型 | 说明 |
|---|---|
| `weather` 查天气 | 填城市（不填用 `weatherCity`）。**固定输出三块：天气 + 穿搭 + 运势**（见下方说明） |
| `text` 固定文案 | 每次都发同一句，适合「该打卡签到了！」 |
| `llm` 让 AI 现写 | 给一句提示词，到点由模型按人设现写。**不联网、查不到真实天气/新闻** |
| `search` 联网查 | 到点联网查一次，再让 AI 挑重点说 |

### 「查天气」为什么三块一定都有（2026-10-30）

```
🌙 石河子市 · 今日天气（10月30日 周五）
现在 5.8℃（体感 2.8℃）· 少云 ｜ 湿度 67% ｜ 西南风 5.8km/h
全天 -0.1℃ ~ 14.4℃ ｜ 降水概率 0% ｜ 紫外线 3（中等）
👕 穿搭：夹克/风衣 + 长袖 + 薄毛衣；昼夜温差 14.5℃，早出晚归多带一件
🔮 运势（娱乐向，别当真）：小吉 · 整体挺顺｜幸运色 麦黄，幸运数字 72｜宜…，忌…
```

- **天气**：open-meteo 真实数据（wttr.in 兜底）
- **穿搭**：本地规则按「最高温 / 昼夜温差 / 降水 / 风 / 紫外线」算 —— 不依赖 AI
- **运势**：按「日期 + 城市」哈希确定性生成，当天固定、隔天变化，标注娱乐向

「AI 润色」只是把这份简报改成她的语气；**它挂了也照样三块齐全**（以前全靠 AI，模型返回空就只剩天气，这是真实事故）。

目标：可指定群（留空 = 默认群，见 `schedulerDefaultRoom`）、可 @ 某人、可附一张表情包。
「忽略安静时段」默认**勾选**——你自己定的提醒，不该被作息时段吞掉。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| 「AI 现写」报「AI 写不出内容：LLM 路由没确定」 | 插件没指定 provider/model，DSH 也没设默认模型 → 去面板「人设模型」页指定一个（或在 DSH 里选个默认模型）。插件现在会自动探一次可用路由兜底，但显式指定最稳 |
| 天气任务发了但没有运势 / 穿衣建议 | AI 润色那步失败、退回原始数据了。查日志 `[定时] 让 AI 写失败`，多数同上；也可以把「AI 润色」取消，直接发原始数据 |
| 「上次结果」一直 `rc=<非0>` | 桥收到了但微信没发出去，多半是微信掉线 / 未登录 |

## 文件与开关

| 项 | 位置 |
|---|---|
| 任务数据 | `<DSH_HOME>/wechat-bot/schedules.json`（和 config.json 分开，写坏不拖累配置） |
| 总开关 | `schedulerEnabled` |
| 检查间隔 | `schedulerCheckMs`，默认 30 秒（改完要热重载插件） |
| 补跑上限 | `schedulerCatchUpMs`，默认 6 小时 |
| 遵守作息 | `schedulerRespectQuiet`，默认 false |
| 默认城市 | `weatherCity` |
| 默认群 | `schedulerDefaultRoom` |

## 几条行为约定（都是刻意设计的）

1. **错过的任务不无脑补跑**。关机一整天，晚上开机不会再补发"早上 9 点的天气"——超过 `schedulerCatchUpMs` 就跳过并直接排下一次，日志里记一条「错过 N 小时，已跳过」。
2. **失败也要排下一次**。否则一个失败任务会被巡检每 30 秒重试一次，把宿主和微信打爆。
3. **演练模式（`dryRun`）下不真发**，只记日志和预览。
4. **定时任务不受机器人总开关 `enabled` 影响**：那是管"要不要回群聊"的；你亲自排的提醒归 `schedulerEnabled` 管。
5. 天气数据来自 open-meteo（免费、免密钥）；它挂了自动降级 wttr.in，返回里带 `degraded:true`。
